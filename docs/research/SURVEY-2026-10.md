# Literature survey · October 2026

Recent work that shaped docs/13 to docs/16, the ADRs 0002 to 0010 and the research tracks. Every arXiv entry below was checked against the arXiv API on 2026-10-29 (title and authors); venues are given only where the source states them. Claude did the first sweep; Gemini 3.8 Flash ran a second sweep, a specification audit and a cross-target memo, whose citations were checked the same way (one author list was wrong and is corrected here). A row says what the work shows and what VeriGraph takes from it.

## Verified code generation by language models

| Work | Shows | VeriGraph takes |
| --- | --- | --- |
| [A benchmark for vericoding](https://arxiv.org/abs/2509.22908) (Bursuc et al., 2025) | 12,504 formal specs; off-the-shelf models verify 82% in Dafny, 44% in Verus, 27% in Lean; pure Dafny verification rose from 68% to 96% in a year | Contracts discharged automatically by SMT are the easiest target for models: VeriGraph's core bet (R-09, G5) |
| [Dafny as Verification-Aware Intermediate Language for Code Generation](https://arxiv.org/abs/2501.06283) (Li, Zetzsche, Somayyajula, 2025) | A verified intermediate language between the request and the shipped code | The same architecture as docs/00, with the graph as the intermediate form |
| [VERINA](https://arxiv.org/abs/2505.23135), [CLEVER](https://arxiv.org/abs/2505.13938), [DafnyBench](https://arxiv.org/abs/2406.08467), [AlphaVerus](https://arxiv.org/abs/2412.06176), [AutoVerus](https://arxiv.org/abs/2409.13082) | Benchmarks and proof-synthesis loops for verified code | Task design for benchmarks/synthesis; G5 counts success only against a reference contract (docs/16) |

## Constrained and verifier-guided decoding

| --- | --- | --- |
| [Type-Constrained Code Generation with Language Models](https://arxiv.org/abs/2504.09246) (Mündler et al., PLDI 2025) | Type-constrained decoding more than halves compilation errors | Tier 2, made exact by define-before-use (ADR 0005, docs/15) |

## Considered and not adopted

- **Wider formula integers** (Gemini audit A-08): the claimed overflow cannot occur; docs/05 now states the induction that shows every term stays below 2^(w−1).
- **Rewriting the Alive2 adapter** (audit A-40): lowering `Result::Err` to `unreachable` is what makes Alive2 fail when a cure rejects an input the original defines, which is the intended check (docs/08).
- **AS_BYTES of a scalar returning an Array** (audit A-06): the real defect, a returned view of a frame value, is closed by VG-T0120 instead, which keeps the M1 example unchanged.
